# ROPE exploration

A personal exploration of RoPE through its connection to Fourier transforms.

[Read the blog](https://gvessere.github.io/rope-investigation/).

## Edit and preview

Edit `index.html` for Part 1 and `rope-in-practice.html` for Part 2; `style.css` controls presentation.
Equations use native MathML, with their LaTeX source in each annotation. The site uses local JavaScript files for the plot viewer and phase-shift example; it has no remote scripts, fonts, or rendering dependencies.

Run `python3 -m http.server 8771` from this directory to preview locally.

## Regenerate every figure

Requires Python 3.9 or newer. From this repository's root:

```sh
python -m pip install -r requirements.txt
python code/figures.py
python -m unittest discover -s code -p 'test_*.py'
```

The pinned packages are NumPy 2.0.2 and Matplotlib 3.9.4.
`code/figures.py` contains every target function, fitting operation, and plot.
It generates `figures/dft-reconstruction.svg`, `figures/frequency-grids.svg`,
`figures/rope-shapes.svg`, `figures/results.json`, and `figures/examples.npz`.
No external data, model weights, or randomness are used to generate figures.
SVG dates are suppressed and IDs are stable. The array archive contains the
samples, predictions, frequencies, and fitted coefficients behind the plots.

The RoPE examples fit 256 scores using 64 geometric frequencies (128 real
coefficients), base 10000, no extra intercept, and ridge penalty 0.001. They
illustrate representational possibilities, not trained-model findings or
long-context performance. Displacement is query position minus key position;
positive values refer to earlier keys.

Tests check arbitrary real DFT reconstruction, the sine/cosine expansion against
explicit query/key rotations, the geometric ratio, and the fit's optimality
condition. GitHub Actions runs these checks and regenerates the figures before
deploying the static site.

## Original model plots and the dynamic viewer

The viewer in `rope-in-practice.html` and `explorers.js` displays all 70 plot pages based on the original data
from the four requested investigation PDFs, with query/key, view, and layer
selectors, previous/next controls, enlargement, and PDF downloads.
Dotted gray angular guides have been added at the union of multiples of π/4
and π/3 (including π/4, π/3, π/2, 2π/3, 3π/4 and their continuations around
the circle). Cartesian guides are labeled rays; phase guides are labeled
vertical lines. Original source hashes and current rendered-file hashes are
recorded separately in `data/observations/manifest.json`. The CSS preserves each image's aspect ratio.

The 56 NPZ files in `data/observations/` are **lossless layer splits** of the
original float32 amplitude/phase arrays: no token subsampling, rounding,
quantization, centering or density binning. Query shape: (28,12,768,64); key
shape: (28,2,2379,64). These saved activations suffice to regenerate the plots
without downloading model weights or rerunning inference.

```sh
python code/reproduce_observations.py --verify
python code/reproduce_observations.py --kind queries --view xy --page 0
python code/reproduce_observations.py --pdf
```

The last command regenerates all 70 PNG pages and all four PDFs. PDF metadata
(e.g. creation dates) may differ; plot data and rendering instructions are
preserved. Before angular guides were added, local verification with the pinned packages
reproduced representative query-Cartesian and key-phase pages pixel for pixel. `--verify` checks every data
chunk hash, shape, finite values, phase range, point count and amplitude-cap
count. The full dataset is about 170 MB and every file is below GitHub's 100 MB
limit. All original plot pages include every saved point; only the phase view's
0–40 amplitude cap clips points.

Provenance: original chat **ROPE investigation**, turns recorded in the manifest.
The model is Qwen/Qwen2.5-1.5B-Instruct. There are 16 prose excerpts from four
Project Gutenberg books, 48 saved queries per excerpt, and 2,379 body keys.
The metadata files retain sample positions, book/paragraph references, original
point-array hashes and original plot range summaries. Learned projection bias
is retained; known positional rotation was removed before plotting. Raw
query/key phase is not a relative query–key phase or causal evidence of shape
translation. No fresh model measurement is claimed here.

The phase-shift widget evaluates the same fitted coefficients from
`figures/shift-examples.json`, generated by `code/figures.py`, at displacement
minus the requested shift. It does not refit. It is a deterministic constructed
example, cropped to show only values from the original fit interval.

## Adjustable scales in the live viewer

The viewer draws **every retained saved point** onto a canvas directly from the
existing per-layer NPZ files. No data files are duplicated or regenerated.
`scatter-data.mjs` reads NumPy ZIP/NPY data using native gzip decompression with
ZIP CRC validation; `scatter-viewer.mjs` performs filtering and plotting.
`data/observations/palette.json` preserves the 64-color turbo palette and is
exported by `code/reproduce_observations.py`.

- The **Autoscale r to the 99th percentile per head** checkbox is on by default.
  It uses linear interpolation of sorted float32 radii with double-precision
  index/interpolation arithmetic, across all saved tokens and 64 pairs in the
  head, before applying the phase window. Ties can retain slightly more than 99%.
- Manual `r min` and `r max` apply the same limits to all shown heads. Editing
  either field turns autoscale off. A blank manual `r max` uses each head's
  complete range. **Show all points** resets the radial and phase filters.
- Phase bounds are entered in units of π. The Cartesian view always preserves
  equal x/y units and symmetric axes; radius filtering also omits points outside
  the selected radial interval that would otherwise fit in square corners.
- Each panel and the summary report how many original points remain visible.
  A head selector helps inspect an individual head. PNG export saves the current
  canvas. The PDF archive retains its published fixed scales.
- Layers load on demand; up to eight decoded layers are cached. First load
  requires native browser gzip decompression. If unavailable or loading fails,
  the fixed-scale image and PDFs remain available.

`node code/test_viewer.mjs` checks NPZ decoding, percentile calculations, full
and manual ranges, and phase-window counts against independent NumPy reference
values for every first-layer query and key head. The fixtures use float64
percentile arithmetic on the saved float32 values. These checks run in CI.

## Observations, pair phases, and recorded quantization experiments

`python code/observations.py` regenerates the L8 H3 query low-radius scatter/density
figure, the two bias-cloud examples, the quantization-results chart, density-bin
arrays, and all numerical observations in `data/analysis/observations-summary.json`.
The source is the existing per-layer activation data, the unmodified projection
bias vectors extracted from the original checkpoint, and the original recorded
quantization results. No inference is needed to rebuild these article figures.
Provenance and source hashes are in `data/analysis/provenance.json`.
The recomputed held-out bias fits are checked against the original experiment.

The 64 dials in the shape-shift widget show unit phasors of the fitted score
coefficients, not captured activations. Their initial phase is atan2(-b_j,a_j)
and their displacement-dependent phase is phi_j - omega_j*t. The common slider
and explicit play/pause button drive the score curve and all dials together.
Lengths are normalized; each tooltip reports the actual coefficient amplitude.
Playback does not start automatically; the same button pauses it. Browsers normally suspend animation frames in background tabs.

To rerun the model intervention (separate from regenerating the article figures):

```sh
python -m pip install -r requirements-model.txt
python code/run_phase_quantization.py --device mps --output rerun-results.json
# For the first weight download, add --allow-download.
```

The model revision is pinned to 989aa7980e4cf806f80c7fef2b1adb7bc71aa306.
The runner consumes the saved public-prose token IDs, checks projection biases
against the saved checkpoint, and applies the intervention before RoPE in every
layer. It evaluates all 7,168 target positions and checks an identity roundtrip.
CPU and CUDA are also selectable. Reference results were float32, eager attention,
MPS, PyTorch 2.8.0, Transformers 4.57.6. Backend differences can change outputs.
The new portable runner has not been used to produce new benchmark numbers here;
the article explicitly presents the original recorded runs. Its intervention
implementation was tested for radius, scope, and prefix preservation, and the
Torch implementation was compared with the independent NumPy implementation.
The regular site dependencies do not require downloading model weights.

Bias conclusions distinguish a constant additive bias from an input-dependent
query/key vector. Density figures and phase rounding do not establish universal
preferred angles. The related direct-pair PolarQuant paper is Wu et al.,
arXiv:2502.00527; the distinct preconditioned PolarQuant paper is arXiv:2502.02617.

## Translation evidence: L23 H4, pairs 16–31

Run `python code/translation.py` to regenerate the three translation figures.
This independently recomputes diagnostic profile correlations, local phase-rescue
metrics, the phase-scale fit, and table-bootstrap intervals from the posted
`data/translation/L23-H4-captures.npz` and prompts. It verifies agreement with the
original saved metrics and summary, verifies fixed query positions and rigid key
relocations, and checks the geometric translation identity and preserved pair radii.
Output-effect intervals are recomputed from the original per-prompt intervention
measurements. This requires only the main requirements, with no model download.

The captures are a lossless extraction of layer 23, head 4, final assistant-prefix
query from the original 2026-10-22 confirmation run. Q/K are post-RoPE, split-half
coordinates `(j,j+64)`. The query position is held fixed across placements, so its
known positional rotation cannot explain the phase differences. The candidate and
discovery-fitted correction scale were frozen before 32 new confirmation tables.
The highest-band exploratory failure is retained in the article and original report.
The source was selected after an exploratory search; this is not a preregistered
initial candidate or evidence for universal natural attention translation.

`data/translation/provenance.json` records hashes and array layouts;
`locked-selection.json` records the frozen choice; `prompts.json` contains all
384 prompts and native answers; `output-interventions.json` contains the 1,024
first-token measurements (256 moved prompts × four modes). The figures are
reanalyses of these saved measurements, not fresh inference. No inference runner
for this original experiment is implied by the lightweight plotting command.
Full-vocabulary target probability and first-token accuracy did not improve, and
the geometric correction was worse than the native phase on target-label log odds.

## Recorded GPU speed comparison

`python code/speed_results.py` verifies hashes, recomputes attention trial medians,
whole-model counterbalanced decode medians, speed ratios against grouped dense
attention, and paired quality deltas. It updates both article tables and
`data/speed/recomputed-summary.json`. No new hardware measurement is performed.
The original attention, repeated decode, and quality runs are posted under
`data/speed/`. The attention comparison uses M5 Max float32 MPS, native 32k
layer-10 K/V. The full-model comparison uses Qwen2.5-1.5B, batch 1, with shared
exact dense prefill excluded. Larger microbenchmark batches repeat three real
contexts. The 4+4-bit compact-scoring prototype retains full original K/V and
is distinct from the small, slow-pair phase-only intervention. It is not an
official PolarQuant reproduction. Run-to-run timing variation is substantial.

## Slow-frequency explanation

`python code/slow_frequencies.py` regenerates the period/basis figure and
`data/analysis/slow-frequencies.json` from the posted Qwen config at revision
989aa7980e4cf806f80c7fef2b1adb7bc71aa306. It verifies the geometric schedule,
counts the last five pairs below 0.1 radians per configured window, and checks
the uniform cosine score-change bound numerically across phases and offsets.
This is an analytic illustration, not measured model attention. Small positional
rotation does not imply that setting a learned content phase to zero is harmless.
The constructed approximation examples intentionally retain their B=10,000
setting. The optional archived slow-frequency illustration uses the actual model's B=1,000,000 and is no longer displayed in the article.

The detailed L23 H4 translation experiment is presented in
`archive/attention-displacement-2026-11-12.html`, outside the active series. Original asset paths are preserved, so all figures,
data, and reproduction-code links continue to resolve.

## All-position quantization and the separate bias-removal result

Run `python code/recompute_phase_results.py` before `python code/observations.py`.
