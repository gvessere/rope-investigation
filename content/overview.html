I wanted to understand how a transformer knows where to look. RoPE seemed like a good place to start. The more I looked at it, the more it began to resemble another familiar idea: building a shape out of waves.

The usual explanation is that RoPE rotates query and key vectors so their similarity depends on the distance between them. That explains the mechanism. What I wanted to know was what the mechanism could do.

Could a head look for something eighty tokens ago? Could it prefer a whole neighborhood rather than one position? Could it avoid a region? And if all of that was possible, did trained models actually use it?

Those questions became this exploration. I’ll begin with a single pair of numbers, work up to the Fourier connection, and then turn to the measurements. The code and experimental details are there to follow further, but the pictures and the questions are the main thread.

Start with the problem: the same words, in a different order

“The dog followed the child” and “The child followed the dog” contain the same words. To distinguish them, a model needs more than a collection of token identities. It needs some way to use their arrangement.

Attention gives each token a query and compares it with keys from the other tokens. The scores determine how their value vectors are mixed together. Positional encodings give those comparisons information about where the tokens occur.

There are several ways to do this. We can add position vectors to token representations, or add a distance bias to attention scores. RoPE takes a geometric approach: it rotates the queries and keys before comparing them.

Follow just one rotating pair

A whole attention head has many coordinates. For now, keep only two. Think of the query as an arrow in a plane and the key as another arrow. Their dot product is largest when they point the same way, zero when they are perpendicular, and negative when they point in opposite directions.

Now let position rotate each arrow. At position 10, an arrow has turned ten times as far as it had at position 1. If both arrows move forward by the same number of positions, both turn by the same extra angle. Their angle relative to each other stays the same.

That is the useful trick. The comparison remembers the separation between the positions, without depending on which position we happened to call zero.

Here it is in one equation. A query at position \(m\) and a key at position \(n\) are compared as

\[(R(m\omega)q)^\top R(n\omega)k=q^\top R((n-m)\omega)k.\]

\(R\) is an ordinary two-dimensional rotation; \(\omega\) is how far it turns per token. The absolute positions have become the relative displacement \(n-m\). This is the central construction in RoFormer.

The rotation, written out \[R(\phi)=\begin{pmatrix}\cos\phi&-\sin\phi\\\sin\phi&\cos\phi\end{pmatrix}.\]

For the calculations in these notes, positive displacement means key position minus query position. In causal attention, earlier keys therefore have negative displacement. When I discuss a positive “age,” I mean distance into the past instead.

Move the key, and a wave appears

Hold the query and key content fixed, and imagine sliding the key through different positions. Its rotated arrow turns. Sometimes the arrows align; a little later they are perpendicular; later still they oppose each other.

The resulting score is a sinusoid. One rotating pair gives us one wave:

\[s_j(\Delta)=r_j\cos(\omega_j\Delta-\theta_j).\]

The frequency \(\omega_j\) tells us how quickly the score changes with distance. The phase \(\theta_j\) shifts the wave sideways. The amplitude \(r_j\) tells us how much that pair can contribute.

Changing the phase moves this preference. A phase of zero puts a maximum at the reference point; π puts a minimum there. At π/2 the contribution at that point is zero, but the wave still has preferences elsewhere. A negative contribution can discourage a match without excluding it from attention.

So one pair can prefer some distances and discourage others. But it repeats. It cannot, by itself, mean “look around eighty tokens back, and nowhere else.” That would need a different shape.

Give the head more than one wave

RoPE uses many coordinate pairs, each rotating at a different speed. Some turn quickly; others barely change over a short stretch of text. The head adds their contributions.

The standard schedule spaces the speeds geometrically: each frequency is the previous one multiplied by the same ratio. In the usual notation,

\[\omega_j=B^{-2j/d}.\]

\(B\) sets the range of scales and \(d\) is the head dimension. The picture below uses the schedule from our Qwen model. Notice how the frequencies form a straight line on a logarithmic vertical axis. There are fast and slow scales, rather than one common positional clock.

And this was the connection that interested me: if the score is a sum of waves, could those waves combine into a useful positional shape?

That sounds like a Fourier transform

A Fourier transform takes a sampled shape and describes it using sinusoidal components. Reverse the process—add the components back together—and the shape returns. A peak, a plateau, or an irregular outline can all be assembled from waves.

RoPE gives attention a related set of ingredients. Its query and key vectors determine how strongly each wave contributes and where it sits. That suggests a way to think about a head’s positional score: as a shape that its components can build together.

There is a catch worth keeping in mind as we explore. The complete DFT has a carefully chosen frequency grid that can reconstruct any sequence of samples on its window. RoPE uses a different grid, with a limited number of components. Sharing the ingredients does not give it the same reconstruction guarantee.

Rather than leave the connection as an analogy, the next step is to draw a target and try to build it. That lets us see both the possibilities and the restrictions.

How the waves come out of the dot product

With \(\Delta=n-m\), expanding each rotation gives

\[s(\Delta)=\frac1{\sqrt d}\sum_j[A_j\cos(\omega_j\Delta)+B_j\sin(\omega_j\Delta)],\] \[A_j=q_{jx}k_{jx}+q_{jy}k_{jy},\qquad B_j=q_{jy}k_{jx}-q_{jx}k_{jy}.\]

The coefficients depend on the query and key content. These are therefore fixed-content distance sweeps, rather than a claim that every real token pair shares one positional function. The sign convention is checked against direct rotations in the code. Qwen’s actual pairs use split-half coordinates \((j,j+64)\).
